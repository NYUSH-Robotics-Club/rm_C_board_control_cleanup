# 启动顺序与 LED

`Src/main.c` 完成初始化后进入裸机循环，没有调用 `RobotRtos_Start()` 或
`AppRuntime_Step()`。LED 只能定位大致阶段，不能替代日志和反馈。

| 顺序 | 颜色 | 阶段 | 可能等待 |
|---:|---|---|---|
| 1 | 红 | CubeMX 外设完成，开始软件初始化 | 无 |
| 2 | 黄 | 消息中心、日志、CAN、电机、云台初始化 | 无固定 CAN 延时 |
| 3 | 青 | 等 yaw/pitch 反馈并锁存实际上电位置 | 最长 5 秒 |
| 4 | 蓝 | IMU 校准，仅配置启用时出现 | 由校准实现决定 |
| 5 | 品红 | Cmd、底盘、发射订阅初始化 | 无 |
| 6 | 品红 | 哨兵舵轮对齐，仅 sentry | 最长 5 秒 |
| 7 | 白 | 遥控、视觉、ESC 等待、WT61C DMA | ESC 200 ms |
| 8 | 绿 | 进入裸机主循环 | 持续 |

## 关键顺序

1. HAL、时钟、GPIO、DMA、CAN、SPI、I2C、UART、USB、TIM 初始化。
2. 初始化消息中心和 Logger，然后启动 CAN manager；任一路初始化/启动失败即
   进入安全错误状态。
3. `MotorService_Init()` 先校验整套电机配置并初始化厂商 adapter；失败即停止
   启动。随后 `MotorDriver_ModuleInit()` 装载当前车型的 DJI 兼容状态。
4. `GimbalApp_Init()` 后调用 `Gimbal_WaitForAlignment()`。控制器只有在两轴反馈
   有效后才锁存当前角度并输出保持电流。
5. 若车型启用 IMU 校准，校准期间每约 5 ms 发布零速保持命令；反馈未就绪时
   云台仍输出零，不会追固定角度。
6. 初始化 Cmd、底盘、发射、遥控、视觉和 WT61C。
7. 进入 `while (1)` 裸机循环；不启动 RTOS。

## 初始化后的周期

主循环进行 IMU 更新、命令处理、消息派发、LED 与限流 CAN 统计，最后
`HAL_Delay(CMD_REFRESH_INTERVAL_MS)`。电机服务在派发后的 hook 中刷新。
周期包含处理耗时，不能声称是严格 1 ms；未调用预留 RTOS 的可选应用步进和蜂鸣器更新。

## 云台仍突跳时检查

1. yaw/pitch 的 CAN RX ID 与通道是否正确，首帧是否都在 5 秒内到达；
2. 两轴锁存目标是否等于首帧角度；
3. `direction`、pitch 重力补偿符号和编码器环绕是否正确；
4. 是否有其他模块在上电锁存完成前发送非零电流；
5. PID 是否在捕获位置后清零。

本次仅核正文档，冻结底层没有修改；启用 RTOS 需另行授权，不能随环境升级接入。
