## 核心接口总览

### 1. 主程序入口 - `robot.h`

这是整个机器人程序的入口点，提供了两个核心接口：

```c
/**
 * @brief 机器人初始化,请在开启rtos之前调用.这也是唯一需要放入main函数的函数
 */
void RobotInit();

/**
 * @brief 机器人任务,放入实时系统以一定频率运行,内部会调用各个应用的任务
 */
void RobotTask();
```

**使用方法：**
- 在 `main()` 函数中（Src/main.c,Line 78），**在启动RTOS之前**调用 `RobotInit()`
- 在RTOS任务中，以 **200Hz-500Hz** 的频率调用 `RobotTask()`（推荐200Hz，若需要更高实时性可提升至1kHz）

### 2. 配置定义 - `robot_def.h`

**重要：这是必须修改的文件！**

该文件包含所有机器人参数配置，**必须根据每个机器人的实际情况进行修改**。

#### 2.1 开发板类型定义（必须选择一个）

```c
#define ONE_BOARD      // 单板控制整车
// #define CHASSIS_BOARD // 底盘板（双板模式）
// #define GIMBAL_BOARD  // 云台板（双板模式）
```

**注意：** 只能存在一个定义，否则编译会报错。

#### 2.2 视觉通信方式（可选）

```c
#define VISION_USE_VCP   // 使用虚拟串口发送视觉数据
// #define VISION_USE_UART // 使用串口发送视觉数据
```

#### 2.3 机器人参数配置（必须修改）

**云台参数：**
- `YAW_CHASSIS_ALIGN_ECD`: 云台和底盘对齐时的编码器值
- `YAW_ECD_GREATER_THAN_4096`: ALIGN_ECD值是否大于4096
- `PITCH_HORIZON_ECD`: 云台水平位置时的编码器值
- `PITCH_MAX_ANGLE`: 云台竖直方向最大角度
- `PITCH_MIN_ANGLE`: 云台竖直方向最小角度

**发射参数：**
- `ONE_BULLET_DELTA_ANGLE`: 发射一发弹丸拨盘转动的距离
- `REDUCTION_RATIO_LOADER`: 拨盘电机减速比
- `NUM_PER_CIRCLE`: 拨盘一圈的装载量

**底盘参数（单位：mm）：**
- `WHEEL_BASE`: 纵向轴距（前进后退方向）
- `TRACK_WIDTH`: 横向轮距（左右平移方向）
- `CENTER_GIMBAL_OFFSET_X`: 云台旋转中心距底盘几何中心的距离（前后方向）
- `CENTER_GIMBAL_OFFSET_Y`: 云台旋转中心距底盘几何中心的距离（左右方向）
- `RADIUS_WHEEL`: 轮子半径
- `REDUCTION_RATIO_WHEEL`: 电机减速比

**陀螺仪方向：**
- `GYRO2GIMBAL_DIR_YAW`: 陀螺仪yaw方向（1为相同，-1为相反）
- `GYRO2GIMBAL_DIR_PITCH`: 陀螺仪pitch方向
- `GYRO2GIMBAL_DIR_ROLL`: 陀螺仪roll方向

#### 2.4 数据结构定义

该文件还定义了应用间通信的数据结构，包括：

- `Chassis_Ctrl_Cmd_s`: 底盘控制命令（由robot_cmd发布，chassis订阅）
- `Gimbal_Ctrl_Cmd_s`: 云台控制命令（由robot_cmd发布，gimbal订阅）
- `Shoot_Ctrl_Cmd_s`: 发射控制命令（由robot_cmd发布，shoot订阅）
- `Chassis_Upload_Data_s`: 底盘反馈数据（由chassis发布，robot_cmd订阅）
- `Gimbal_Upload_Data_s`: 云台反馈数据（由gimbal发布，robot_cmd订阅）
- `Shoot_Upload_Data_s`: 发射反馈数据（由shoot发布，robot_cmd订阅）

**注意：** 所有用于通信的结构体都使用 `#pragma pack(1)` 包裹，取消字节对齐。

### 3. 命令模块 - `cmd/robot_cmd.h`

机器人核心控制模块，负责接收控制指令并转化为具体控制信息。

```c
/**
 * @brief 机器人核心控制任务初始化,会被RobotInit()调用
 */
void RobotCMDInit();

/**
 * @brief 机器人核心控制任务,200Hz频率运行(必须高于视觉发送频率)
 */
void RobotCMDTask();
```

**功能：**
- 接收遥控器/上位机/键鼠/视觉的控制指令
- 将控制指令转化为具体的控制信息
- 发布控制命令给其他应用（gimbal/chassis/shoot）
- 订阅其他应用的反馈信息
- 处理紧急停止和离线检测

**发布的话题：**
- `chassis_cmd`: 底盘控制命令
- `gimbal_cmd`: 云台控制命令
- `shoot_cmd`: 发射控制命令

**订阅的话题：**
- `chassis_feed`: 底盘反馈数据
- `gimbal_feed`: 云台反馈数据
- `shoot_feed`: 发射反馈数据

### 7.RTOS相关
RTOS 启动流程
在 main.c 中，RTOS 启动分为两步：
1. 初始化 RTOS 对象（第128行）

MX_FREERTOS_Init();

该函数在 freertos.c 中定义，用于：
创建任务（如 defaultTask）
创建互斥锁、信号量、队列等（如需要）
初始化定时器（如需要）

2. 启动调度器（第131行）

osKernelStart();

启动 FreeRTOS 调度器，开始多任务调度。调用后，控制权交给调度器，main 函数中的 while(1) 循环不会被执行。
当前状态
RTOS 已配置并启动
已创建一个默认任务 defaultTask（在 freertos.c 第106-107行）
默认任务启动后立即终止（第128行）
如何添加自己的任务
在 freertos.c 的 MX_FREERTOS_Init() 函数中添加任务创建代码：
/* USER CODE BEGIN RTOS_THREADS */
/* 添加线程，例如： */
osThreadDef(myTask, MyTaskFunction, osPriorityNormal, 0, 128);
osThreadCreate(osThread(myTask), NULL);
/* USER CODE END RTOS_THREADS */

### 第四步：配置RTOS任务

在 `robot_task.h` 中已经定义了任务初始化函数 `OSTaskInit()`，该函数会创建以下任务：

- **INS Task** (1kHz): 姿态解算任务
- **Motor Task** (1kHz): 电机控制任务
- **Daemon Task** (100Hz): 守护任务
- **Robot Task** (200Hz): 机器人核心任务（调用 `RobotTask()`）
- **UI Task**: UI任务

**注意：** `OSTaskInit()` 会在 `RobotInit()` 内部被调用，无需手动调用。

### 第五步：理解应用间通信机制

所有应用通过 **消息中心（message_center）** 进行通信，采用发布-订阅机制：

- **发布者（Publisher）**：通过 `PubRegister()` 注册话题，通过 `PubPushMessage()` 发布消息
- **订阅者（Subscriber）**：通过 `SubRegister()` 订阅话题，通过 `SubGetMessage()` 获取消息

**话题名称：**
- `chassis_cmd`: 底盘控制命令
- `gimbal_cmd`: 云台控制命令
- `shoot_cmd`: 发射控制命令
- `chassis_feed`: 底盘反馈数据
- `gimbal_feed`: 云台反馈数据
- `shoot_feed`: 发射反馈数据

各模块通过 消息中心 通信，无需直接包含其他模块头文件：
话题名	        数据类型	             发布者	         订阅者
gimbal_cmd	    Gimbal_Ctrl_Cmd_s	    robot_cmd	   gimbal
gimbal_feed	    Gimbal_Upload_Data_s	gimbal	       robot_cmd
chassis_cmd	    Chassis_Ctrl_Cmd_s	    robot_cmd	   chassis
chassis_feed	Chassis_Upload_Data_s	chassis	       robot_cmd
shoot_cmd	    Shoot_Ctrl_Cmd_s	    robot_cmd	   shoot
shoot_feed	    Shoot_Upload_Data_s	    shoot	       robot_cmd


### 第六步：双板模式配置（如适用）

如果使用双板模式：

1. **云台板**：定义 `GIMBAL_BOARD`，包含 robot_cmd、gimbal、shoot 应用
2. **底盘板**：定义 `CHASSIS_BOARD`，包含 chassis 应用
3. **板间通信**：通过CAN总线进行通信，注意避免ID冲突和负载过大

### 怎么调用与修改？
- **调用**：`robot_cmd` 通过 `message_center` 发布 `*_cmd` 话题，`gimbal/chassis/shoot` 订阅后在各自 `*Task()` 中读取并生效。
- **修改入口**：
  1. **新增/调整模式**：先改 `application/robot_def.h` 的枚举。
  2. **决定“什么时候进入该模式”**：改 `application/cmd/robot_cmd.c` 的 `RemoteControlSet()` / `MouseKeySet()` / 离线逻辑。
  3. **定义具体行为**：改 `application/gimbal.c` / `application/chassis.c` / `application/shoot.c` 的 `switch (xxx_mode)` 分支逻辑。


## 有关debug

### 调试和性能分析（摘录原文）

- 基础的调试可以在VSCode中完成。cortex-debug插件的最新版本已经支持多个gdb-server（jlink/stlink/openocd/pyocd）的live watch（动态变量监视）和变量示波器（可视化）。若不是有特别的需求，*请勿使用串口调试器*。

- 有高速变量查看和数据记录、多路数据可视化的需求（如进行pid参数整定、查找难以定位的bug）时，使用**Segger Ozone**。
- FreeMaster也可以作为调试的备选项。
- 基本的、日常性能分析可以通过`bsp_dwt`完成。若要分析关于任务运行和每个函数执行的详细信息和时间，推荐使用**Segger Systemviewer**。

### 其它
Ozone 调试：工程里有 debug_ozone.jdebug，直接用 Ozone 打开即可；也能从 task.ps1 里走 debug_ozone 任务。
SystemView：配合 Segger 工具链运行（用于实时任务分析）。
RTT 日志：工程已有支持，配合 RTT 终端查看（VSCode 任务里一般有对应入口）。


## 重要注意事项

1. **不要使用全局变量**：应用间通信必须通过消息中心
2. **应用间无包含关系**：各应用是平行的，不应相互包含
3. **初始化顺序**：`RobotInit()` 必须在RTOS启动前调用
4. **任务频率**：
   - INS Task: 必须1kHz
   - Motor Task: 推荐200Hz-1000Hz
   - Robot Task: 推荐200Hz以上，必须高于视觉发送频率
   - Daemon Task: 100Hz
5. **参数配置**：必须根据实际机器人修改 `robot_def.h` 中的所有参数
6. **数据结构对齐**：用于通信的结构体必须使用 `#pragma pack(1)` 包裹
