# 步兵失联与故障处理核查

2026-09-11，已随发射联锁更新，依据当前工作区 `infantry_standard`，未核对板上镜像、未主动断线或烧录。
时间阈值都由主循环/消息派发检查，实际动作会叠加调度延迟，不是硬件定时停机保证。

## 失联后的动作与恢复

以下“归零”指软件命令为零；断线电机未必能收到该命令，机械也不会瞬间停稳。
电调自身断通信行为及超时时间本轮未核验。

| 对象 | 判断 | 软件反应 | 恢复 |
|---|---|---|---|
| 遥控器接收层 | daemon每约10ms减计数，reload=10，正常循环约100～110ms无接收回调 | 清上游解码缓存，尝试重启USART3 DMA，累加warning；HAL_BUSY只记录，不强制abort | 新接收回调重载daemon；只有完整18字节帧发布给命令层 |
| 遥控命令层 | 距最近收到完整遥控消息超过200ms | 三类命令清空；底盘四轮及云台两轴归零、清PID，拨弹归零；摩擦轮目标以每命令500RPM降到0，再做零速闭环，反馈失效才归零电流 | 遥控离线不撤销CAN armed。重连后底盘可直接响应新摇杆，云台等100ms反馈有效再锁当前位置；发射需右拨杆重新经过下档 |
| 底盘软件ID1/2/3/4，CAN1 RX201/202/203/204 | 任一从未收到反馈或反馈年龄>100ms | 全部四轮命令归零，重置四轮速度/电流PID；云台和发射不因这个局部条件停止 | 四轮反馈全部有效且当前命令启用后自动恢复，不要求重新回中；目标不由失联检查清空 |
| yaw软件ID5，CAN1 RX209 | 运行时控制间隔/反馈间隔/反馈年龄>20ms，或跟踪编码/位移/速度非法；还有双轴100ms反馈门限 | yaw/pitch同时归零，清PID/连续历史/耦合历史；中档底盘在yaw反馈年龄>20ms或方位非法时也停止；下档和spin无此底盘方位联锁 | 满足双轴反馈检查并等待100ms，重新锁存实际位置；yaw当前仅调速度环，不提供位置保持 |
| pitch软件ID8，CAN2 RX208 | 从未反馈或反馈年龄>100ms | pitch/yaw同时归零，pitch重力补偿和前馈也停止；底盘及发射无pitch离线联锁 | 同上，等待100ms并重新锁存两轴当前位置 |
| 左摩擦轮软件ID6，CAN2 RX201 | 从未反馈或反馈年龄>100ms | 三台发射电机归零，清全部目标、斜坡、PID和输出 | 三台反馈全部新鲜且CAN已解锁后按当前命令从零爬升 |
| 右摩擦轮软件ID7，CAN2 RX202 | 同上 | 同上，联锁整个发射机构 | 同上 |
| 拨弹软件ID9，CAN2 RX203 | 同上 | 同上，联锁整个发射机构 | 同上 |
| 任一路CAN Bus-Off | ESR.BOFF | 锁住全车非零CAN输出，中止两路待发邮箱；软件发送缓存清零，进入总线恢复状态机 | 两路无BOFF/EPVF/EWGF保持500ms后，再双拨杆下、五轴在±3内保持500ms解锁；随后各应用仍需满足反馈条件 |

遥控daemon清空的是上游缓存，不会主动发布一条清零消息，因此不能把约100ms重启接收
当作应用层已经停机。命令层依靠独立的200ms检查。

yaw连续控制检查失败不一定代表电机物理断线；主循环卡顿超过20ms也会触发。
中档底盘只核对yaw方位，不因pitch失联或yaw前馈参数错误自动停止。

CAN恢复中：中止邮箱/进入初始化步骤超时20ms；退出初始化/总线同步超时1000ms；
失败等待1000ms再试。错误警告EWGF、错误被动EPVF阻止新的解锁并打断健康计时，
**已解锁时并不会仅因这两位撤销armed**；Bus-Off才触发上述全车锁定。

依据：`application/cmd/{cmd_controller,command_router}.c`、
`application/chassis/chassis_controller.c`、`application/gimbal/{gimbal_controller,yaw_reference}.c`、
`application/shoot/shooter_controller.c`、`bsp/can/bsp_can.c`、`modules/can_comm/can_manager.c`。

## 能取得的反馈

| 渠道 | 目前能看到什么 | 限制 |
|---|---|---|
| C板RGB灯 | 新报警模块支持红灯硬件ID、蓝灯分组 | 已接入主循环，全部电机在线时亮绿；见[报码说明](motor-offline-alarm.md) |
| 蜂鸣器 | 新报警模块支持每组按CAN总线号鸣叫 | 已接入主循环；遥控单独失联尚未加入报警 |
| USB CDC日志 | 云台初始化/补偿输出；其他模块已有部分日志代码 | RC/CAN/CHA/SHO/CMD等标签默认0，只有GIM开启；没有逐电机离线/恢复事件，USB忙时发送失败会被忽略 |
| 遥控内存诊断 | `BspRc_GetDiagnostics()`的收帧、TC/IDLE、UART错误、重启尝试、BUSY、warning；`RC_GetFrameCount()`及最后18字节帧 | warning文本被端口宏改为计数；旧通道缓存本身不代表在线，须结合计数变化及命令接收时间 |
| 电机/应用内存 | `MotorService_GetSnapshot()`的角度/RPM/原始电流/反馈时间，以及应用PID、目标、输出和反馈有效标志 | `feedback_valid`不包含年龄超时判断，必须计算now-反馈时间；失联后显示的数值可能只是最后一帧 |
| CAN诊断 | 每总线rx_frames/last_rx_id/tx_ok/tx_err，ESR/TSR/RF0R，恢复phase、fault/recovery/timeout计数 | tx_ok只代表成功提交邮箱，不证明电机收到或动作；总线接收增长不证明每个节点在线 |
| 消息中心诊断 | 各主题发布/派发/覆盖/合并/拒绝计数 | 可定位软件分发问题，不直接等同物理链路故障 |

这些诊断主要要通过匹配固件ELF的SWD读取，或后续接入状态发布。现有
`Debug_PrintCANStatus/Debug_PrintCANDiag/Debug_PrintRCDiagnostics`未在当前主循环调用。
运行中SWD只读禁止`verify_image/checksum`等会占目标RAM的校验，镜像需dump后主机比较。

## 已发现的缺口

1. 发射三台失联联锁已补齐；未到速禁止拨弹、云台失联禁止发射仍未实现。
2. 遥控重连和多数电机重连会自动恢复，只有CAN Bus-Off走总输出重新解锁；摩擦轮反馈
   恢复现在从零爬升。恢复策略不是全车统一的。
3. 电机离线位图/报码模块已接入主循环；尚无逐设备离线/恢复事件时间记录。
4. 超时检查依赖命令任务与派发继续运行；没有看到独立命令过期看门狗或已启用的IWDG/WWDG。
   `Src/main.c:Error_Handler`只关中断死循环，HardFault等也死循环，未主动发送零命令或自动复位；
   遥控和电机普通失联不走Error_Handler。异常后的物理停机不能由这些循环保证。
5. 发射控制已新增首帧seen标志，封住开机100ms内全零时间戳被当成新鲜反馈的边界。
