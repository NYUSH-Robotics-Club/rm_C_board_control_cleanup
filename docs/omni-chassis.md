# 四轮全向底盘

当前代码已实现参数化的四轮全向逆运动学；步兵选择 `CHASSIS_TYPE_OMNI`。
用户已确认几何并填入配置，`g_omni_infantry.configured=1`：X形 ±45°，前后、左右轮中心距
均0.54 m，轮半径0.07 m，M3508 配套 P19。电机安装正反向仍需首次架空核对。
这版尚未烧录。遥控接收、两轴云台协议、CAN 波特率和裸机调度没有修改。

## 已确认的硬件映射

俯视，车头朝上：

```text
          车头 / +x
     左前 ID3    右前 ID2
  +y ←       中心
     左后 ID4    右后 ID1
```

| 轮位 | CAN1 电调 ID | 反馈 ID | 0x200 控制帧字节 |
|---|---:|---|---|
| 左前 | 3 | 0x203 | 4、5 |
| 右前 | 2 | 0x202 | 2、3 |
| 右后 | 1 | 0x201 | 0、1 |
| 左后 | 4 | 0x204 | 6、7 |

运动学数组按左前、右前、右后、左后排列，即 **3、2、1、4**。
控制器按逻辑电机 ID 查配置、接收反馈，发送层按 `tx_slot` 打包。
轮位顺序不会改变 C620 要求的报文字节顺序。

## 手册依据与换算

仓库 [C620 使用说明](official-docs/Robomaster_C620_Docs.pdf) PDF 第14–17页：

- ID1–4 使用标准 CAN 数据帧 `0x200`、DLC=8；每个电机占两个字节，高字节先发。
- 原始电流命令 ±16384 对应 ±20 A；不是 RPM 命令。
- 反馈 ID 为 `0x200 + 电调ID`，转子速度单位为 RPM，转子角度为 0–8191。
- 默认反馈频率 1 kHz；本次没有修改电调参数。

仓库 M3508 使用说明 v1.0（2025.10）描述的是裸电机；用户已另行确认使用 P19。
采用 [DJI 官方 P19 使用说明 v1.0（2017.08）](https://rm-static.djicdn.com/tem/17348/RoboMaster%20M3508%E7%9B%B4%E6%B5%81%E6%97%A0%E5%88%B7%E5%87%8F%E9%80%9F%E7%94%B5%E6%9C%BA%E4%BD%BF%E7%94%A8%E8%AF%B4%E6%98%8EV1.0%EF%BC%88%E4%B8%AD%E8%8B%B1%E6%97%A5%EF%BC%89.pdf)
PDF第7页给出的精确减速比 **3591/187 ≈ 19.2032**。
减速比含义为“电机转子转数 / 轮子转数”，本配置按 P19 输出轴直接驱动轮子处理，只乘一次。

定义车体速度 `vx` 向前、`vy` 向左，单位 m/s；`wz` 俯视逆时针为正，
单位 rad/s。对第 i 个轮子：

- 轮中心相对底盘中心为 `(x_i, y_i)`，单位 m。
- 主动滚动正方向单位向量为 `(tx_i, ty_i)`，长度为1。这不是轮轴方向，也不是被动小滚子的方向。
- 轮半径为 `r_i`，单位 m；减速比为 `G_i > 0`。

```text
v_wheel_i = tx_i * vx + ty_i * vy + (x_i * ty_i - y_i * tx_i) * wz
motor_rpm_i = v_wheel_i / r_i * 60 / (2*pi) * G_i
signed_target_i = MotorConfig.direction_i * motor_rpm_i
```

这是刚体轮心速度在驱动方向上的投影。可描述 X 形、沿四边安装或非对称全向轮，
不套用麦轮滚子公式；若布局不能独立实现前后、横移和旋转，则拒绝输出。

输入命令先归一化：平移矢量长度最多1，旋转分量限制在 ±1。再乘
`max_translation_mps` 与 `max_rotation_radps`。当前拟定初调上限为
0.30 m/s、0.60 rad/s，这两个是控制速度设定，不是已测得的机械性能。
四个转子目标若超过公共 RPM 上限，就全部等比例缩小，保持组合运动方向；
上限取 `CHASSIS_DEMO_TARGET_SPEED` 和四个电机 `speed_limit` 的最小值。

速度 PID 用有符号转子 RPM 做闭环，输出 C620 电流刻度，再由已有电机服务发送。
本次保留四个轮子的原速度 PID 参数，尚未进行新底盘的实车调参。

## 本车已填入的参数

参数在 [步兵配置](../config/robots/infantry_standard.c) 的 `g_omni_infantry`。
半轮距、半轴距均为0.27 m；四轮坐标为 `(±0.27, ±0.27)`。为便于核对，驱动正向
统一取向前分量为正：左前/右后为 `(1,-1)/sqrt(2)`，右前/左后为 `(1,1)/sqrt(2)`。
它们只是轮子运动的正向定义，实际转子正负由 `MotorConfig.direction` 匹配。

用本车尺寸化简后，令 `K=60*G/(2*pi*0.07*sqrt(2))≈1852.3888`，物理速度输入
仍为 m/s 和 rad/s，未乘电机方向的转子 RPM 为：

```text
左前 ID3: K * (vx - vy - 0.54*wz)
右前 ID2: K * (vx + vy + 0.54*wz)
右后 ID1: K * (vx - vy + 0.54*wz)
左后 ID4: K * (vx + vy - 0.54*wz)
```

因此0.30 m/s纯前进时每轮目标绝对值约555.72转子RPM；0.60 rad/s纯自转时约600.17 RPM。
生产代码采用通用向量投影，以上为方便手算的本车等价式。

`MotorConfig.direction` 只取 ±1，仅在目标处应用一次；反馈保留原始有符号值。
当前沿用 ID1/2/3/4 = -1/+1/+1/-1，尚未实测新安装方向。首次架空低速核对；若某轮
反向，只修改该电机 `direction`，不要同时翻转反馈或更换 CAN 槽位。几何不完整时可将
`configured` 置0，底盘会直接零输出。

遥控通道绑定沿用现有路由：普通模式（左拨杆下）为
`vx=-ch3/660`、`vy=-ch2/660`、`wz=ch4/660`（含原有死区）。
中/上档仍使用原有云台参考/小陀螺路由，本次未校准两套 IMU 的坐标与初始朝向，
因此首次核对全向轮方向应使用普通模式。

## 停机与验证

缺少几何、非有限参数、非单位驱动向量、重复电机映射或不可运动的布局时，
运动学返回未就绪/参数错误并清空输出。无效映射不会把零指令发给 yaw 等其他角色。

底盘命令禁用时直接给四轮零电流并重置 PID。全向轮必须全部收到真实反馈；
任何一个轮子超过100 ms没有反馈，四轮都置零电流，收到新鲜反馈后恢复计算。
这只作用于底盘，不增加底盘离线对云台的联锁。零电流代表不主动驱动，车辆会有惯性。

`tests/host/test_chassis_strategies.c` 使用明确的合成几何验证三轴基向量、
组合运动、反向、斜向限速、轮径/减速比换算、排列变换、整体限幅以及参数拒绝。
`tests/host/test_omni_controller.c` 使用真实消息中心、运动学、速度 PID 和 CAN 聚合，
仅以桩替代电机服务转发、时间、日志和 BSP；捕获 CAN1 0x200 检查四个 ID 的字节槽位，
以及缺反馈、单轮离线、禁用、非法映射的零输出。测试数值未写入实车配置。

主机全套测试和两车型 Debug ARM 构建已通过；均未链接 RTOS 入口。
实际生产几何也通过主机集成测试，验证555.72/600.17 RPM及对应CAN槽位。
尚未烧录、读取新固件运行状态或做实车方向测试；不能把编译通过等同于四轮方向已验证。
